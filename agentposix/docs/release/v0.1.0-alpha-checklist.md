# Release Checklist & Capability Matrix (`v0.1.0-alpha`)

This document outlines the capability matrix, supported and unsupported scenarios, and migration notes for the first alpha release of Agent POSIX (`v0.1.0-alpha`).

---

## 1. Supported Scenarios & Capabilities

The following capabilities are fully implemented, verified via tests, and ready for use in experimental or early-stage systems:

- **Lifecycle Protocol Validation:** Strict state transition validation (e.g., `INITIALIZING` -> `RUNNING` -> `CHECKPOINTED` -> `RESUMING`). Illegal lifecycle transitions raise deterministic `StateTransitionError`s.
- **Durable Filesystem storage:** High-durability checkpoint persistence utilizing:
  - Atomic replace-on-write writes (via temporary files and `os.replace`).
  - Strict OS cache sync flushing (`flush` + `os.fsync`) for both files and parent directory metadata.
  - Per-session in-process writer locks to serialize writers.
- **SQLite Storage Backend:** Asynchronous checkpoint persistence using SQLite in Write-Ahead Logging (WAL) mode for higher concurrency and performance.
- **Pydantic Model Serialization:** Deterministic schema serialization conforming to Pydantic v2 metadata configurations and standard JSON constraints.
- **Integrity Checksum Validation:** Automated SHA-256 validation on reading and resuming to reject tampered or corrupted state checkpoints.
- **Host Drift Detection:** Captures runtime environments (directory, platform, Python version) on freeze and validates them on resume, raising `HostDriftError` for fatal drift or recording advisories in `extensions["resume_advisories"]`.
- **LangGraph Checkpoint saver Adapter:** Maps and saves/restores LangGraph threads, checkpoint versions, channel states, metadata, and pending writes inside namespaced extensions.
- **CLI Commands:** Shell utilities to inspect (`agentposix inspect`), resume (`agentposix resume`), or debug-freeze (`agentposix freeze`) checkpoint states.

---

## 2. Unsupported Scenarios (Out of Scope)

The following scenarios are currently **unsupported** in the `v0.1.0-alpha` release and must be handled by external application coordination if required:

- **Cross-Process Coordination/Locking:** Filesystem locks are in-process only. Multiple separate Python processes writing to the same filesystem backend directory simultaneously will experience race conditions.
- **Automatic Schema Migrations:** There is no built-in schema migration system for storage backends. If a future release updates the `AgentStateObject` model, older stored files/DB rows may fail validation with `InvalidASOError` until manually patched.
- **Real-Time Synchronization:** Active replication, DB replication, or network storage sync is not handled by the library.
- **Non-JSON-Serializable Decorator Replays:** The `checkpoint_boundary` decorator raises `SideEffectReplayError` if a duplicate call returns a non-JSON-serializable value (such as complex python class objects), as it cannot safely mock/replay them.

---

## 3. Migration and Compatibility Notes

- **Python Requirements:** Python `>=3.10` is strictly required. Tests are run on `3.10`, `3.11`, and `3.12`.
- **Integrations and Extras:**
  - Standard installs include the CLI, filesystem storage, and basic schema validation.
  - SQLite backend requires `pip install agentposix[storage]`.
  - LangGraph adapter requires `pip install agentposix[adapters]`.
- **Future Breaking Changes:** As an alpha release, APIs under the `agentposix` namespace may undergo minor changes in subsequent pre-release patches before the `1.0.0` stable version.
